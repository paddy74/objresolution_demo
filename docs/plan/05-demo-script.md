## Outcome first

> "Today every brief starts with a debate about how many objects there really are. ## How the layers compound (the one story)

| Layer                  | Its own value                                                                                                                            | What it hands to the next layer                                                                                                                                                      |
| ---------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 1. Governed foundation | One entity (the Object) across Postgres-style, tasking, JSON feed and report sources, with lineage columns and ontology-conformant types | Clean joins and CCO type compatibility become the model's **features** (`type_score`, `type_missing`); `source_file` and `ingested_at` make every score traceable                    |
| 2. Predictive model    | A match probability per observation-to-object pair, not a guess                                                                          | The probability **routes the work**: `AUTO` needs no human, `REVIEW` goes to an analyst, `NOMINATE` clusters the leftovers into new objects. Analyst decisions become **new labels** |
| 3. GenAI               | A short dossier that explains an object and **cites** the observations and reports it used                                               | The dossier reads the foundation and the model's probabilities, so it explains the model's uncertainty instead of hiding it                                                          |
| 4. Presentation        | One view from ingest to decision to write-back                                                                                           | The approval **MERGEs** back into the object system, the object count moves, and the decision becomes a label: the loop closes                                                       |

Compounding in one sentence: **the foundation makes the model possible, the model decides who does the work, the dossier explains and cites, and the analyst's decision feeds the next model.**

## Disclosure moments ("synthetic")

Say it plainly three times, so it never sounds like an apology:

1. **Slide 3 / start of notebook:** "Everything you will see is synthetic. The sources are mocked: the Postgres object system and the MySQL tasking system are Delta tables and files here."
2. **Model results:** "These precision numbers are on synthetic data, and the labels stand in for past analyst adjudications. They show the mechanism, not real-world accuracy. In production the labels come from your analysts' review queue."
3. **Closing:** "In production I would not mock the sources: Lakehouse Federation or change data capture from the real databases, which I have not run in this environment."

## The recovery philosophy (say it if something breaks)

> "That is exactly why I keep a saved run: it is also what an operational pipeline gives you, a run you can inspect after the fact."

Then use the saved output or screenshot and keep going. Do not debug live in front of the customer.
